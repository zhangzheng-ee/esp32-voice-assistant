# ESP32-S3 + INMP441 麦克风踩坑与现状（2026-11-21 凌晨）

## 一、目标与当前结果

**目标**：让 INMP441 数字麦克风录到能听懂的语音，为阶段 5（AI 语音助手）铺路。

**当前结果**：**能录到信号，能测到你说话的基频（169Hz），但听不清内容。**
定位为「一位之差」的代码问题，不是硬件问题。

---

## 二、今晚已经解决的坑（5 个）

### 坑 1：面包板电源轨必须由板子供电

- **现象**：把设备都接到红轨/蓝轨，但没从板子引线，设备全不通电
- **原因**：面包板电源轨只是两条独立的金属条，电源轨之间不连通，也不会自己去别处取电
- **修法**：板子 3V3 → 红轨引一根、板子 GND → 蓝轨引一根，之后所有设备从轨上取电
- **判据**：红轨 4 条线（板子3V3 / 屏VCC / 麦VDD / 功放SD）、蓝轨 5 条线（板子GND / 屏GND / 麦GND / **麦L/R** / 功放GND）

### 坑 2：两个 "SD" 不是一回事

- **现象**：以为麦的 SD 和功放的 SD 都接 3V3
- **原因**：功放 SD = Shutdown 开关脚（接 3V3 才工作）；麦克风 SD = Serial Data 数据脚（接 GPIO6）
- **修法**：功放 SD → 3V3；麦克风 SD → GPIO6
- **判据**：丝印上麦克风那排是 `L/R WS SCK`（左列）和 `GND VDD SD`（右列），**SD 在右列最下**

### 坑 3：I2S MONO 模式导致 BCLK 少一半（最容易踩的配置坑）

- **现象**：串口打印 `rms=23170` **永远不变**、`peak=32767`（int16 饱和）、`nonzero=512/512`
- **原因**：`I2S_SLOT_MODE_MONO` + 32bit + 16kHz 时，ESP32 只输出 **32×fs = 512kHz** 的 BCLK；
  而 INMP441 是标准 I2S 从机，需要 **64×fs = 1024kHz**（左右各 32 位）。时钟少一半 → 时序错位 → 读到固定错误模式
- **诊断细节**：`23170 = 32767 ÷ √2` = 满幅正弦的 RMS，看着像信号，其实是时序错位后的残片
- **修法**：`.slot_cfg` 改用 `I2S_SLOT_MODE_STEREO`，读到的数组交替 L/R，**取偶数索引**（L/R 脚接 GND = 左声道）
- **判据**：改完 rms 从「恒定 23170」变成「60~450 持续波动」

### 坑 4：SD 数据线虚接

- **现象**：rms 有小变化但峰值永远上不去（最大 578），`峰值/RMS ≈ 1.3`（正常音频应 3~5）
- **原因**：SD 是麦克风 → ESP32 的数据线，这根线虚接/劣质时，时钟通了但数据出不来
- **修法**：只换 SD 那根线（GPIO6）
- **结果**：换后最大 rms 从 578 跳到 **29394（90% FS）**
- **判据**：`peak/rms` 接近 1、或"永远读到同一个特别大的值" → **先换线，别先改代码**

### 坑 5：I2S 启动瞬间的 DMA 瞬态

- **现象**：每次开始录的头 20~30ms 是一个 **-21000 的方波尖峰 + RC 充电衰减**，`ALLMAX=29394` 从第一行就出现
- **原因**：DMA 缓冲未初始化 + 麦克风上电稳定过程，不是真实声音
- **修法**：录音前先读掉 **0.5 秒**（`for (i=0; i<(SR/2)/128; i++) i2s_channel_read(...)`）
- **判据**：采集数据时前 0.5 秒必须丢弃，否则分析结果全是假的

## 三、当前卡点（今晚没解决的）

### 现象

```
段0: std=1462  语音带(200-3000Hz)占比=53.9%  动态范围=3.2x
峰值频点: 169Hz, 168Hz, 168Hz, 168Hz, 169Hz, 167Hz, 169Hz, 167Hz
50ms 包络: 2135 813 966 1064 1356 1040 614 644 1451 1540 2028 1952
```

**翻译**：

- **169Hz = 男声基频**（男声 85–180Hz），说明**麦克风确实在录人说话**
- **包络有 3.2 倍起伏**，说明有音节节奏（不是死噪声）
- **但只有基频，没有谐波和共振峰** → 听起来只有"嗡"，分不出是哪个字

### 正常应该有的东西

```
基频 169Hz
├─ 2次谐波 338Hz
├─ 3次谐波 507Hz
├─ ...
└─ 共振峰 500Hz / 1500Hz / 2500Hz   ← 决定"听得出是哪个字"
```

### 三个怀疑方向（按可能性排序）

**① 24bit 数据位对齐错了（最可能）**

INMP441 输出 24 位数据，装进 32 位容器里可能是**左对齐**也可能是**右对齐**。
当前代码 `raw[i] >> 8 >> 8`（等于取高 16 位）**假设了左对齐**。

如果实际是右对齐，等于把 24 位截成 8 位有效 —— **精度几乎全丢，高频被削平，只剩最底下的低频**。
这和"只有基频没有谐波"的现象**完全吻合**。

线索：之前抓到的 raw 值 `FFFFFFFE` / `7FFFFFFE`，**低 8 位不是干净的 0**（是 0xFE），说明数据不是标准的左对齐 24bit。

**验证方法**：把同一段数据用 4 种方式解析，看哪种能出谐波

```c
(int16_t)(raw[i] >> 16)      // 取高16位（当前做法，等于 >>8 >>8）
(int16_t)(raw[i] >> 8)       // 取24位的高16位
(int16_t)(raw[i] & 0xFFFF)   // 取低16位
(int16_t)(raw[i])            // 直接截断
```

**② 增益过高导致削顶**

v11 的 round1 出现 `peak=-32768 clip=123`（削顶 123 个样本）。
`GAIN 32` 可能太大，削顶会制造大量谐波失真 —— 但**这只会让声音变脏，不会让谐波消失**，所以不是主因。

**③ 麦克风供电/接地噪声**

原始信号 std=6671（低频噪声），高通后只剩 442 —— 说明低频噪声比信号大 15 倍。
可能是面包板供电不稳或地线环路。**但这解释不了"没有谐波"**。

## 四、明天第一步（10 分钟）

**只改一行，试 4 种解析方式。**

在 `mictest.ino` 的录音循环里，把：

```c
int32_t v = raw[i] >> 8;
gBuf[n++] = hp((float)(v >> 8));
```

**判据**：哪个版本能出现 338Hz / 507Hz / 676Hz 这些谐波，哪个就是对的。

## 六、面试可以怎么讲（阶段 4 这段）

> "INMP441 接上后一直读到恒定的 23170，换算一下是 32767 除以根号二，满幅正弦的 RMS——但真麦克风不可能输出恒定值。顺着这个数往下查，发现是我把 I2S 配成了 MONO 模式，BCLK 只有 32 倍采样率，而标准 I2S 从机要 64 倍，时钟少一半导致时序错位。改成 STEREO 之后数据开始波动了。后来又发现读到的数据峰值上不去，检查发现是数据线虚接，换线后峰值从 578 跳到 29000。这两个坑都不是查文档能查到的，是逐个排除变量试出来的。"

**为什么这段话值钱**：它证明了你能从"一个数字"推到"一个配置项"，而不是换个教程照抄。



## 坑1：MONO 模式 BCLK 只有一半
现象：rms 恒定 23170（=32767/√2）
原因：I2S_SLOT_MODE_MONO + 32bit 只给 32×fs，INMP441 要 64×fs
修法：改 I2S_SLOT_MODE_STEREO，读偶数索引


## 坑2：SD 线虚接
现象：peak/rms ≈ 1.3，读到的全是满幅极值
原因：劣质杜邦线，数据线接触不良
修法：只换 SD 那根


## 坑3：录音窗口 vs 传输窗口
现象：室友说话录得到，自己说话录不到
原因：27 秒周期只有 3 秒在录，89% 概率错过
修法：屏幕变白 = 正在录，变黑 = 在传
