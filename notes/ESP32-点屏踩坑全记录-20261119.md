# ESP32-S3 点屏踩坑全记录（2026-11-19）

硬件：ESP32-S3 DevKitC N16R8（16MB Flash / 8MB Octal PSRAM）
屏：1.28" 圆屏 GC9A01 240×240，排针 VCC GND SCL SDA DC CS RST
环境：Arduino IDE 2.3.11 + esp32 core 3.2.1-cn（arduino.me 镜像）

---

## A. 环境与工具

### A1. esp32 开发板包下载失败
- **现象**：`Failed to install platform 'esp32:3.3.12'. 13 INTERNAL: Download failed: ... dial tcp 20.247.166.64:443: connectex: A connection attempt failed`
- **原因**：GitHub releases 被墙，crosstool-NG 工具链单文件 700MB
- **修法**：首选项 → 附加开发板管理器网址填 `https://arduino.me/packages/esp32.json`（下载域名全指向 `dl.espressif.cn`），装 `3.2.1-cn`
- **判据**：`Invoke-WebRequest https://github.com -Method Head` 直连超时；`espressif.github.io` 能开但 `github.com/...releases/download/` 不能

### A2. 板子有两个 Type-C 口，插哪个
- **现象**：两个口都在底部并排
- **区别**：左口 `VID_303A&PID_4001`（Espressif 原生 USB，免驱，PID 会变）；右口 `VID_1A86&PID_55D3`（CH343，系统自带驱动）
- **修法**：**用右口（CH343）**
- **判据**：设备管理器出现 `USB-Enhanced-SERIAL CH343 (COMx)` 且 Status OK

### A3. USB CDC On Boot 设错导致串口全无输出
- **现象**：上传成功，但串口监视器一个字都没有
- **原因**：Enabled = Serial 输出走 USB 外设（需原生 USB 口接电脑）；Disabled = 走 UART0（GPIO43/44，经 CH343 转 USB）
- **修法**：**用 CH343 口时必须设 Disabled**
- **附带收益**：换 Disabled 后固件 363094→305842 字节（-57KB flash），RAM 40364→20376（-20KB）
- **判据**：串口能打出 `ESP32-S3 / 2核 / 240MHz / Flash 16MB / PSRAM 8MB`

## B. 编译

### B1. `redefinition of 'void setup()'`
- **原因**：新代码粘到了旧模板后面，文件里有两份 setup/loop
- **修法**：`Ctrl+A` → `Delete` 清空 → 再粘
- **判据**：报错会同时指向两组行号（如第 1 与 10 行、第 6 与 24 行）

### B2. `'BLACK' was not declared in this scope`
- **原因**：GFX Library for Arduino 1.6.9 没把颜色宏导出到全局
- **修法**：颜色一律写 RGB565 数值
  - 黑 `0x0000` 白 `0xFFFF` 红 `0xF800` 绿 `0x07E0` 蓝 `0x001F` 黄 `0xFFE0` 青 `0x07FF` 品红 `0xF81F`

### B3. `xxx.h: No such file or directory`
- **原因**：sketch 还在 `C:\Users\...\Temp\.arduinoIDE-unsaved...\sketch_nov19c\`（未保存），而头文件在 D 盘
- **修法**：先"另存为"到 D 盘项目目录
- **教训**：`xxx.h: No such file` 是**文件位置问题**，不是代码问题

### B4. 编译几分钟不结束
- **原因**：首次编译要编整个 esp32 核心库（60+ 个 .cpp），正常 1–3 分钟
- **判据**：任务管理器里能看到几十个 `xtensa-esp32s3-elf-g++.exe` 在跑
- **注意**：**别点 Cancel**，等它跑完

## C. 上传与串口

### C1. `Failed to connect to ESP32-S3: No serial data received`
- **原因**：原生 USB 口没有 `DTR/RTS → RST/BOOT` 物理电路，`Hard resetting via RTS pin` 是假的，芯片进不了下载模式
- **修法**：换 CH343 口；换过去后 `Connecting...` **一个点就连上，不用按 BOOT**
- **判据**：日志出现 `Connected to ESP32-S3 on COMx` + `Hash of data verified`

### C2. 端口号一路跳（COM7 → COM8 → COM9）
- **原因**：**PID 从 `4001` 变 `1001`**（4001 = 用户程序 TinyUSB CDC；1001 = 芯片自带 USB-Serial-JTAG/下载模式），Windows 每次重新枚举设备、分配新端口
- **修法**：每次上传前看一眼设备管理器确认当前端口
- **判据**：`Get-PnpDevice -Class Ports` 里 PID 是 4001 还是 1001

### C3. 程序其实在跑，但串口看不到
- **原因**：见 A3（USB CDC 设置）
- **验证手段**：用 pwsh 手动拉 DTR/RTS 复位后读串口，能读到堆大小说明程序活着

## D. 显示

### D1. `#include <U8g2lib.h>` 编译 5–15 分钟
- **原因**：U8g2 把整个字体库（几千个字体、几 MB 的 `u8g2_fonts.c`）全编进去
- **这不是卡死**，每次改代码都要重来一遍

### D2. 字模代码跑通了但屏幕全黑（核心坑）
- **原因**：**U8g2 是单色库（1 bit），GC9A01 是 16 位彩色 TFT，U8g2 的驱动列表里根本没有 GC9A01**
- **判据**：在 U8g2 的 `u8g2_d_setup.c` 里搜 `GC9A01`，搜不到
- **正解两条路**：
  - 路 A（推荐，已验证）：图片路线 —— `Arduino_GFX_Library` + `draw16bitRGBBitmap`
  - 路 B：`U8g2_for_Adafruit_GFX` —— 把字模当贴图画到 gfx 画布上
    - `u8g2Fonts.begin(*gfx)` 必须在 `gfx->begin()` **之后**
    - `setFontMode(1)` = 透明背景
    - **`setCursor(x, y)` 的 y 是文字基线，不是顶部**
    - `setForegroundColor(0xFFFF)`

### D3. 文字是竖着显示的
- **原因**：`Arduino_GC9A01(bus, TFT_RST, 0, true)` 第三个参数是 rotation
- **修法**：改成 1 / 2 / 3 试，`1` 或 `3` 是横屏

### D4. 屏引脚顺序和网上教程不一样
- **实测丝印**：`VCC GND SCL SDA DC CS RST`
- **注意**：**DC 在 CS 前面**（常见模块是 CS 在前）；`RST` 就是 `RES`
- **接线（已跑通）**：VCC→3V3（**接 5V 会烧**）、GND→GND、SCL→GPIO12、SDA→GPIO11、DC→GPIO9、CS→GPIO10、RST→GPIO14

## E. 图像流水线

### E1. 换图几分钟没反应
- **原因①**：老脚本用 PowerShell 逐像素循环，57600 个像素每个都 `("0x{0:X4}" -f $v)` 格式化字符串
- **原因②**：`.ps1` 缺 UTF-8 BOM，Windows PowerShell 5.1 按 GBK 解码 → 中文注释乱码 → 脚本解析失败（报 `Unexpected token 'KB'` / `Missing closing '}'` 连锁错）
- **修法**：改用 `Add-Type` 内联 C# 类 `ImgConv`；所有 .ps1 写 UTF-8 BOM（`239,187,191`）
- **结果**：1024×1024 → 240×240 **0.96 秒**

### E2. 把图片拖到 bat 上不触发
- **修法**：改成双击 -> `pick.ps1` 弹 `OpenFileDialog` 选图 -> 直接生成 `plantest\image.h`
- **原则**：不依赖拖拽这种"用户操作姿势"

### E3. flash 空间预算
- 每张 240×240 图 = **112.5KB**（57600 个 uint16）
- app 分区 3MB，核心库 400KB，超过 8 张图就要改分区或改用 FATFS（9.9MB）

## F. 资源冲突

### F1. CPU 89% / GPU 100% / 内存 79%
- **实测**：GPU 7310/8151 MiB
- **占用者**：混元 2mv 建模 8.9GB 内存 + LM Studio 的 Qwen3-8B（`n-gpu-layers 999999` 全塞显存，约 5GB）
- **风险**：8GB 卡上 5GB + 4GB = 9GB，**混元随时 OOM**
- **修法**：跑混元前先 unload LM Studio 的模型（`Stop-Process -Id <llama-server PID> -Force`）

## G. 一条通用教训

> **每个坑都记成四行：现象 / 原因 / 怎么修的 / 下次怎么快速判断。**
> 判断顺序永远是"先怀疑最便宜的东西"：线是不是充电线 -> 端口号对不对 -> 设置项对不对 -> 才轮到驱动和代码。
