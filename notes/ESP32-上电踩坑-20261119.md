## 坑 1：esp32 开发板包下载失败（GitHub 被墙）

**现象**

```
Failed to install platform: 'esp32:3.3.12'. 13 INTERNAL: Download failed:
performing HEAD request: ... dial tcp 20.247.166.64:443: connectex:
A connection attempt failed because the connected party did not properly respond
```

**原因**

包索引里的下载地址全部指向 `github.com`，releases 文件走 Azure CDN（20.247.x.x），国内直连超时。注意 `espressif.github.io` 是能开的——**索引能下、文件下不来**，这个组合很有迷惑性。

**修法**

首选项 → 附加开发板管理器网址 → 换成 arduino.me 镜像：

```
https://arduino.me/packages/esp32.json
```

这个源里所有下载地址都改成了 `dl.espressif.cn`（乐鑫国内 CDN），速度正常。版本会显示成 `3.2.1-cn`，`-cn` 只是国内站标记。

**判据**

- `espressif.github.io` 能打开 ✅
- `github.com` 上的 `.zip` 下不来 ❌
- → 就是被墙，换镜像

**备用方案**

下载官方索引，把里面 1441 处 `https://github.com/` 全部替换成 `https://ghfast.top/https://github.com/`，存成本地文件后用 `file:///D:/...` 路径加载。

**现象**

```
Compilation error: redefinition of 'void setup()'
```

错误里同时指向第 1 行和第 10 行的 `void setup()`，第 6 行和第 24 行的 `void loop()`。

**原因**

`Ctrl+A` 全选 → `Delete` 删干净（界面变白纸）→ 再粘贴。

**判据**

看报错行号，出现**两组** setup/loop 就是粘重了。

## 坑 3：上传报 `Failed to connect` / `No serial data received`

**现象**

```
Connecting..........................
A fatal error occurred: Failed to connect to ESP32-S3: No serial data received.
```

**原因**

板子没进 bootloader。用的是**原生 USB 口（USB-Serial-JTAG）**，这个口不像 CH340/CH343 那样有 `DTR/RTS → RST/BOOT` 的复位电路，esptool 没法自己把板子拽进下载模式。

**修法**

手动进下载模式：

```
① 按住 BOOT 不放
② 点一下 RST（点完立刻松开 RST）
③ 再松开 BOOT
④ 立刻点上传
```

**判据**

设备管理器里 ESP32 的 USB 设备 **PID 从 4001 变成 1001**。

- `PID 4001` = 用户程序的 USB CDC（TinyUSB）
- `PID 1001` = 芯片自带的 USB-Serial-JTAG / 下载模式

## 坑 4：端口号一直在跳（COM7 → COM8 → COM9）

**现象**

```
A fatal error occurred: Could not open COM7, the port is busy or doesn't exist.
```

每按一次 BOOT+RST，端口号就变一次。

**原因**

ESP32-S3 的 USB 有**两种工作模式**，对应两个不同设备，切换 = USB 重新枚举 = 分配新 COM 号：

| PID    | 含义                                |
| ------ | --------------------------------- |
| `1001` | USB-Serial-JTAG（芯片硬件外设，下载/调试用）    |
| `4001` | USB CDC（程序里的 TinyUSB，Serial 输出走这） |

而且 Windows 会把断开的旧设备**留在列表里**（状态 Unknown），很容易选错。

**修法**

每次操作前先看「工具 → 端口」确认当前是几号。根治办法是换 CH343 口（见坑 6）。

**判据**

端口列表里同时有 `OK` 和 `Unknown` 两个同名设备 → 选 **OK** 那个。

## 坑 5：烧录成功，但串口一个字都没有

**现象**

```
Hash of data verified.
Hard resetting via RTS pin...
```

——但串口监视器一片空白。

**原因（两层）**

1. **`Hard resetting via RTS pin` 在原生 USB 口上是假的。** 没有 RTS 到 NRST 的物理连线，esptool 只是发了条命令，芯片没真复位，还停在 bootloader 里。
2. 即使复位了，如果插左边口而 `USB CDC On Boot` 设成 Disabled，`Serial` 会走 UART 引脚（GPIO43/44），USB 那边收不到。

**修法**

手动按 RST；或对串口对象拉 DTR/RTS 强制复位：

```powershell
$p = New-Object System.IO.Ports.SerialPort('COM9',115200)
$p.Open()
$p.DtrEnable = $true; $p.RtsEnable = $true
Start-Sleep -Milliseconds 150
$p.DtrEnable = $false; $p.RtsEnable = $false
Start-Sleep -Milliseconds 200
$p.ReadExisting()
```

**判据**

读到的第一行如果是 `[73 秒] 运行中，可用堆 318 KB` 这种，说明**程序早就在跑**，只是没连对通道。

## 坑 6：换 CH343 口后必须改 USB CDC 设置

**现象**

换到右边 Type-C 口（CH343），系统识别出 COM10 且状态 OK，但 `Serial` 没输出。

**原因**

两条**完全独立**的物理通道：

| 口        | 通路                                  |
| -------- | ----------------------------------- |
| 左边原生 USB | 芯片 USB 外设 → 程序里的 TinyUSB CDC        |
| 右边 CH343 | 芯片 UART0（GPIO43/44）→ CH343 芯片 → USB |

`USB CDC On Boot = Enabled` 的意思是「把 Serial 输出交给 USB 外设」。插 CH343 口时那条线在物理上是空的，输出全跑空气里了。

**修法**

用 CH343 口时 → `USB CDC On Boot` 改成 **Disabled**。

**判据**

CH343 口的收益（换过去就不用再折腾）：

- 有 `DTR/RTS → RST/BOOT` 真电路，**自动进下载、自动复位**
- 上传和看串口是**同一个 COM 口**，不跳号
- 代价：Serial 走 UART，不经过 TinyUSB

---

## 一句话总结

**原生 USB 口（USB-Serial-JTAG）看着高级，但没自动复位电路**：下载要手按 BOOT、端口每次换号、复位还是假的。
**CH343 那个口才是干活用的** —— Win10/11 自带驱动（`VID_1A86&PID_55D3`），插上就是稳定一个 COM 号。
