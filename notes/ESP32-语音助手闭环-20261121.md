## 三、接线表（已验证跑通）

**屏幕 GC9A01（SPI）**
```
VCC → 3V3      GND → GND
SCL → GPIO12   SDA → GPIO11
DC  → GPIO9    CS  → GPIO10    RST → GPIO14
```
⚠️ 屏是 **3.3V**，接 5V 立刻烧。7 针无 BLK 脚，不能调亮度。
⚠️ 排针丝印顺序是 `VCC GND SCL SDA DC CS RST`，**DC 在 CS 前面**，与常见模块不同。

**麦克风 INMP441（I2S RX）**
```
VDD → 3V3      GND → GND      L/R → GND（必须接地！）
SCK → GPIO4    WS  → GPIO5    SD  → GPIO6
```
⚠️ **丝印是两列对角分布**：左列 `L/R / WS / SCK`，右列 `GND / VDD / SD`。最容易数错。

**功放 MAX98357（I2S TX）**
```
VIN → 5V（直接从板子 5V 脚引，不要走面包板电源轨）
GND → GND      SD → 3V3（悬空=静音）
BCLK → GPIO15  LRC → GPIO16   DIN → GPIO17
喇叭接 "+" / "−" 两个绿色螺丝端子
```
⚠️ **输出是 BTL 桥接，`+`/`−` 都是活输出，任一端接 GND 就短路烧输出级。**
⚠️ GAIN 悬空 = 9dB（GND=15dB，VDD=3dB）。
⚠️ 单声道功放，**只接一个喇叭**（两个 8Ω 并联成 4Ω 会过热）。

## 五、31 个坑（按阶段）

### A. 环境 / 工具（3 个）

**1. Arduino 开发板包下载失败**
- 现象：`Failed to install platform 'esp32:3.3.12'. 13 INTERNAL: Download failed: ... github.com/espressif/crosstool-NG/...connectex: A connection attempt failed`
- 原因：GitHub releases 被墙
- 修法：首选项 → 附加开发板管理器网址填 `https://arduino.me/packages/esp32.json`（国内镜像，最高 3.2.1-cn）
- 判据：能装上 `esp32 by Espressif Systems`

**2. 所有 .ps1 脚本跑不动，报 `Unexpected token 'KB'`**
- 原因：**文件缺 UTF-8 BOM**，Windows PowerShell 5.1 按 GBK 解码 → 中文注释乱码 → 语法错误
- 修法：`$enc = New-Object System.Text.UTF8Encoding($true); [IO.File]::WriteAllText($f, [IO.File]::ReadAllText($f,[Text.Encoding]::UTF8), $enc)`
- 判据：脚本能跑，中文不乱码

**3. 图片转数组脚本极慢（几十秒到几分钟）**
- 原因：PowerShell 逐像素循环 + 每像素一次字符串格式化 `("0x{0:X4}" -f $v)`，57600 次
- 修法：`Add-Type -ReferencedAssemblies System.Drawing -TypeDefinition $cs` 内联 C# 类做转换
- 效果：**0.96 秒**（1024×1024 → 240×240）

### B. 编译（4 个）

**4. `'BLACK' was not declared`**
- 原因：GFX Library for Arduino 1.6.9 没把颜色宏导出到全局
- 修法：颜色一律写 RGB565 数值：黑 `0x0000` 白 `0xFFFF` 红 `0xF800` 绿 `0x07E0` 蓝 `0x001F`

**5. `redefinition of 'void setup()'`（踩了两次）**
- 原因：新代码粘在旧代码后面，出现两份 setup/loop
- 修法：`Ctrl+A` → `Delete` → 重粘
- **教训：改代码前先清空，不要"在中间插一段"**

**6. `xxx.h: No such file or directory`**
- 原因：sketch 还在 `C:\...\Temp\.arduinoIDE-unsaved...\sketch_nov19c\`，头文件在 D 盘
- 修法：另存到正式目录
- **教训：`xxx.h 找不到` 是文件位置问题，不是代码问题**

**7. U8g2 编译卡 5–15 分钟**
- 原因：`#include <U8g2lib.h>` 把几千个字体（几 MB 的 u8g2_fonts.c）全拉进编译
- 修法：不用 U8g2；文字改用 `text2h.ps1` 渲染成图片
- 额外发现：**U8g2 是单色库（1 位），驱动列表里根本没有 GC9A01 彩屏**

### C. 上传 / 串口（3 个）

**8. 烧录失败 `No serial data received` + 端口号乱跳 COM7→COM8→COM9**
- 原因：板子有两个 Type-C 口。
  - **左口** = 原生 USB（`VID_303A` = Espressif，USB-Serial-JTAG），免驱，但 **PID 会从 4001 跳到 1001**（进下载模式时变），Windows 给新 PID 分配新 COM 号，旧设备留在列表里显示 Unknown
  - **右口** = CH343（`VID_1A86&PID_55D3`），系统自带驱动
- 修法：**改用右口（CH343）**，`USB CDC On Boot` 必须设 `Disabled`（走 UART0 GPIO43/44）
- 收益：一个点就连上（免按 BOOT），flash 少 57KB，RAM 少 20KB
- **教训：原生 USB 口没有 DTR/RTS → RST/BOOT 物理电路，`Hard resetting via RTS pin` 是假的**

**9. 串口一个字都没有**
- 原因：用原生 USB 口时 `USB CDC On Boot = Disabled`，Serial.print 走 UART 引脚 GPIO43/44，物理上没接出去
- 修法：原生 USB 口 → `Enabled`；CH343 口 → `Disabled`

**10. `PermissionError(13, '拒绝访问')`**
- 原因：`serial-monitor` 进程（Arduino IDE 的串口监视器）占着 COM 口
- 修法：`Stop-Process -Name serial-monitor -Force` 再烧

### D. 显示（4 个）

**11. 白屏 / 花屏**
- 原因：PSRAM 没开。N16R8 是 **Octal PSRAM**，Arduino 里默认 `Disabled`
- 修法：Tools → PSRAM → **OPI PSRAM**
- 判据：串口打印 `PSRAM: 8MB Octal`

**12. 图片显示但颜色是反的/错位**
- 原因：RGB565 字节序
- 修法：`draw16bitRGBBitmap` 前确认数组是高字节在前

**13. 文字"竖着"**
- **我的误判**：我说要改 rotation 0→1，用户纠正"我这边是正的，你看针脚"
- **真正的判据：字形正不正。** rotation 错会让字躺倒；字正着排就是对的

**14. 屏幕有一块亮斑，重插 USB 好了**
- 原因：**代码里根本没有屏幕初始化**（没 include Arduino_GFX），屏幕没被驱动，显示的是上电随机残留
- 重插"好了"只是上电随机态变了，不是修好了

### E. 音频（4 个）

**15. 喇叭没声音**
- 原因：**MAX98357 的 SD 脚悬空 = 关机**
- 修法：SD 接 3V3
- 判据：串口有输出、功放不发热、喇叭无电流声

**16. 播放速度翻倍 / 音调变高**
- 原因：**I2S 配的是 STEREO，但喂的是 mono 数据**，硬件按双声道解释 → 采样率感觉翻倍
- 修法：`buf[k*2] = v; buf[k*2+1] = v;`（复制到左右两路）
- **这是 3.x I2S API 最容易踩的坑**

**17. 麦克风读到恒定 `rms=23170`、`peak=32767`**
- 23170 = 32767 ÷ √2 = 满幅正弦的 RMS，**看着像信号，其实是残片**
- 根因有两个，叠加：
  - **`I2S_SLOT_MODE_MONO` + 32bit 时，ESP32 的 BCLK 只有 32×fs（16kHz 时 512kHz），而 INMP441 作为标准 I2S 从机需要 64×fs（左右各 32 位）** → 时钟少一半，时序错位
  - **SD 那根线虚接**：换线后 peak 立刻到 29394（90% 满幅）
- 修法：`.slot_cfg` 用 `I2S_SLOT_MODE_STEREO`，读到的数组交替 L/R，取偶数索引（L/R 接 GND = 左声道）
- **教训：读到"永远同一个值而且特别大"，或 `peak/rms ≈ 1`（正常音频应 3~5），先换线，别先改代码**

**18. 录音听不清 / 静音比说话还响**
- 根因链条很长，最后找到三个叠加问题：
  - **I2S 启动瞬态**：每轮开头 0~23ms 是 -21000 的方波尖峰 + RC 充电衰减 → **必须丢弃前 0.5 秒**
  - **高通切太狠**：200Hz 高通把男声基频（85–180Hz）切掉了 → 降到 80~100Hz
  - **录音窗口 vs 传输窗口错时**：代码是「录 3 秒 → 传 48000 个 hex 约 21 秒 → 间隔 3 秒」，**一个周期 27 秒里只有 3 秒在听（11%）**，说话时 89% 概率落在传输窗口
- 决定性验证：**手指摩擦麦克风芯片**，AVG 从 300~1400 飙到 **12036 / 10533 / 16708**（10 倍）→ 麦克风完全正常
- 最终参数（**已被人声验证，别再动**）：
  ```
  采样率 8000Hz
  I2S 32bit STEREO 取左声道
  GAIN 30
  高通 HP_ALPHA = 0.96f（约 100Hz）
  丢弃前 0.5 秒
  ```
- 判据：rms 3400~6700，频谱 108Hz 基频 + 211Hz 二次谐波（男声特征），语音带 78–83%

**19. `[tts] no data chunk`**
- 原因：跳 HTTP 响应头时用 `readStringUntil('\n')`，**把后面的二进制 WAV 数据也吞掉了**
- 修法：**逐字节读，手动匹配 `\r\n\r\n`**
  ```cpp
  int st = 0;
  while (millis() - th < 8000) {
    if (!client.available()) { if (!client.connected()) break; delay(2); continue; }
    int c = client.read();
    if (c == '\r') { st = (st == 0 || st == 2) ? st + 1 : 1; }
    else if (c == '\n') { if (st == 1) st = 2; else if (st == 3) break; else st = 0; }
    else st = 0;
  }
  ```
- **教训：HTTP 响应头后面是二进制时，绝对不能用行读取函数**

## 六、其他关键经验

**存储：LittleFS 而不是 FATFS**
- esp32s3 菜单原本只有 FATFS，但 **Windows 上做 FAT 镜像要第三方工具，`mklittlefs` 是 core 自带的**
- 自建分区表 `app3M_little12M_16MB.csv`：
  ```
  nvs 0x9000/0x5000 ; otadata 0xe000/0x2000
  app0 0x10000/0x300000 ; spiffs 0x310000/0xCE0000 ; coredump 0xFF0000/0x10000
  ```
  即 **3MB APP + 12.88MB LittleFS**
- 打包：`mklittlefs -c <data> -b 4096 -p 256 -s 0xCE0000 <img>`
- 烧录：`esptool --chip esp32s3 --port COM10 --baud 921600 write_flash 0x310000 <img>`
- 容量换算：**字节/秒 = 采样率 × 2**（22050Hz mono 16bit = 44KB/s，12.88MB ≈ 4分52秒）

**裸 PCM 优于 WAV**
- WAV 头有 chunk 要解析，裸 PCM 直接喂 I2S
- `ffmpeg -i x.mp3 -ar 22050 -ac 1 -f s16le -c:a pcm_s16le x.pcm`

**改 boards.txt 必须重启 IDE**
- `arduino-cli board details` 能看到新菜单，但 IDE 界面看不到（IDE 进程启动早于修改）
- 或者直接用 arduino-cli 绕过

**`esp_sr_16` 分区上传报错**
- `extra_flags=0xD10000 {build.path}/srmodels.bin` 要求额外烧语音模型，但文件不存在
- 修法：把该行值清空

**ESP32 掉端口 = 先做二分法**
- 拔掉负载看端口回不回来。接线不稳时任何调试结论都不可信

**flash 预算**
- 现在用 575KB / 3MB APP
- 大头：WiFi 700KB + U8g2 中文 1MB + HTTPS 150KB + MP3 解码 120KB
- **每张 240×240 图片 = 112.5KB**，超过 8 张要改分区或用 LittleFS
- 8MB PSRAM 是运行时的宽裕（现在只用 22KB）→ **flash 先紧张，PSRAM 不会**

### G. 电脑端服务（4 个）

**20. faster-whisper 报 `open() got an unexpected keyword argument 'metadata_errors'`**
- 原因：faster-whisper 内部用 `av` 解码音频，**`av` 的版本和 faster-whisper 不匹配**（新 av 改了 API）
- 修法：**不用 av**。自己用 `wave` + `numpy` 解码，`resample()` 线性插值到 16000Hz，把 numpy 数组直接传 `model.transcribe()`
- 判据：`v17_2.wav` → `"1 2 3 4 5"`，1.5 秒识别完
- **教训：跑不通先降依赖版本不如绕开依赖**

**21. Windows SAPI 合成直接把进程搞崩**
- 现象：`stream.Format = fmt` 抛 `pywintypes.com_error: (-2147352567, '发生意外。', ..., -2147201022)`；改 `voice.SetOutputToWaveFile(path)` 后**整个 Python 进程直接 exit 1，无任何错误输出**
- 原因：pywin32 的 COM 在非 STA 线程里调用 SAPI 的流接口不稳
- 修法：**不碰 COM，用 PowerShell 子进程**——`System.Speech.Synthesis.SpeechSynthesizer` + `SpeechAudioFormatInfo(22050, Sixteen, Mono)` + `SetOutputToWaveFile`，Python 用 `subprocess.run(["powershell","-NoProfile","-ExecutionPolicy","Bypass","-File",PS1,...])` + 全局锁串行化
- 结果：**1.24 秒**生成 254KB
- **教训：Windows 上有些 API 用 PowerShell 比用 Python 稳**

**22. ASR 输出繁体字**
- 现象：whisper 识别出来是「我給你打個招呼」
- 原因：small 模型的中文输出倾向繁体
- 修法：`pip install opencc-python-reimplemented`，`cc = OpenCC("t2s")`，`text = cc.convert(text)`

**23. 空识别没拦住（`, ` 也发给大模型）**
- 现象：串口打出 `你说：,`，大模型回「你消息发空了」
- 原因：加了过滤 `if not any(("\u4e00" <= ch <= "\u9fff") or ch.isalnum() for ch in text): text = ""`，但**实测没生效**（`", "` 里的逗号不是 alnum，但整句判断逻辑写反了位置）
- 待修

### H. 网络（3 个）

**24. iPhone 热点连不上（没有 2.4G 选项）**
- 现象：ESP32 扫不到 `iPhone`，或扫到但连不上
- 原因：iPhone 12 以后热点默认 5GHz，ESP32-S3 **只支持 2.4GHz**
- 修法：设置 → 个人热点 → 打开 **「最大兼容性」**（开关藏得比较深，找不到就先进「蜂窝网络 → 个人热点」）
- 判据：串口 `alive rssi=-31`（-31 dBm 是满格）

**25. 校园网 HHSTU 连不上**
- 现象：扫到 4 个 HHSTU AP（-67/-75/-83/-85），加密类型全是「开放」
- 原因：**开放 WiFi + 网页 Portal 认证**，ESP32 没有浏览器，过不去
- 修法：用手机热点，别指望校园网

**26. `github.com` 打不开（DNS 污染）**
- 现象：浏览器 `ERR_CONNECTION_TIMED_OUT`，但 `Test-NetConnection github.com -Port 443` 是 True
- 原因：**DNS 被污染**，解析到 `20.6.7.17`（假 IP）
- 诊断：`Resolve-DnsName github.com` 看 IP；用 DoH（`https://223.5.5.5/resolve?name=github.com&type=A`）对比——**阿里 DoH 也返回假 IP 20.247.166.64**，说明污染在链路层
- 修法：改 hosts 写死真实 IP
  ```
  140.82.112.3 github.com
  140.82.112.3 www.github.com
  140.82.112.3 api.github.com
  185.199.108.133 raw.githubusercontent.com
  185.199.108.133 objects.githubusercontent.com
  185.199.108.133 codeload.github.com
  ```
  然后 `ipconfig /flushdns`
- **教训：改 hosts 要管理员权限，用 `Start-Process powershell -Verb RunAs` 提权跑**

### I. GitHub / 工具（3 个）

**27. GitHub HTTPS 时通时不通，但 SSH 一直通**
- 现象：`https://github.com` 有时 200 有时 000（超时），同一时间 `ssh -T git@github.com` 稳定返回 `Hi xxx!`
- 原因：**443 端口的 TLS 被动态干扰，22 端口没被管**
- 修法：**用 SSH 而不是 HTTPS 推代码**
- **教训：`git push` 卡住先换协议试**

**28. git 没装**
- 现象：`Get-Command git` 为空
- 修法：`winget install --id Git.Git -e --source winget --accept-package-agreements --accept-source-agreements --disable-interactivity`
- 装完当前 shell 的 PATH 没刷新，要用完整路径 `C:\Program Files\Git\cmd\git.exe`，或重新读环境变量

**29. PowerShell 脚本几个通用语法坑（连踩）**
- `"第$i次"` → **中文紧跟变量名会被当成变量名的一部分**，要写 `${i}`
- `"{0} {1}" -f $a, (if(...){...}else{...})` → **`if` 是语句不是表达式，不能内联在参数里**，要包成 `$(if(...){...}else{...})`
- `curl` 在 PowerShell 里是 **`Invoke-WebRequest` 的别名**，不是真 curl；要真 curl 用 `C:\Windows\System32\curl.exe`
- **教训：报 `MissingArgument` / `InvalidVariableReferenceWithDrive` 时先看是不是这几个**

### J. 其他（2 个）

**30. `.blend` 文件判类型判错**
- 现象：读文件头只有 4 字节 `BLENDER` 判断，结果说"不是 blend"
- 原因：**Blender 现在默认用 zstd 压缩保存**，文件头是 `28 B5 2F FD`，`BLENDER` 在偏移 12
- 判据：未压缩 = `42 4C 45 4E`（"BLEN"）开头；zstd = `28 B5 2F FD` 开头

**31. M4A 时长解析**
- 读 `mvhd` atom：version 0 时 `timescale` 在 +12、`duration` 在 +16，大端 32 位
- **PowerShell 5.1 不支持 `$bytes[::-1]` 切片**，要用拆字节加法或 `[array]::Reverse`

**一句话版本：**
> 用 ESP32-S3 独立做了一个端到端语音交互设备：INMP441 采集 → WiFi 上传 → 本地 ASR → 大模型 → Edge TTS → MAX98357 播放，全程 7 秒，硬件和固件全部自己调试。

**被问"遇到过什么最难的问题"：**
> 麦克风一直读到恒定的 23170，看着像满幅正弦，其实是坏数据。查了两层：第一层是 ESP32 的 I2S 配了 MONO 模式，BCLK 只有 32 倍采样率，而 INMP441 作为标准 I2S 从机要 64 倍，时钟少一半导致时序错位；改 STEREO 后数据开始变化了，但 peak/rms 比值只有 1.3（正常音频是 3 到 5），说明是直流不是声音，第二层重新排查发现是 SD 数据线虚接，换线后立刻到 90% 满幅。

**被问"你怎么定位问题"：**
> 二分层层排除。先把麦克风的 6 根线全拔掉，看 USB 端口回不回来，确认不是短路；再一根一根插回去，电源、SCK、WS、SD 每步都验端口；最后用手指摩擦麦克风芯片做物理激励，AVG 从 300 飙到 12000，证明器件本身是好的，问题在数字链路。
